## Design Specificity Verdict

The Settings page is functionally specific to Ops Toolshed but visually category-interchangeable. Its Prisma, Aura, campaign-navigation, and Loading Facts content is appropriately product-aware; the generic stack of equally weighted grey toggle strips does not make those feature clusters, benefits, or risks legible.

The deterministic detector returned one `single-font` warning at `settings.html:7`. This is a likely false positive: Outfit is loaded as a variable-weight family, and the detector cannot assess actual type hierarchy from the stylesheet link alone.

## Overall Impression

The surface begins calmly and feels competent, but the Features tab quickly becomes an audit of disconnected decisions. The direct task tabs, especially Loading Facts, demonstrate the stronger pattern: a named job, a concise explanation, an actionable control, and a visible result. The largest opportunity is to turn feature inventory into a navigable set of small, outcome-led groups.

## What's Working

- Semantic, URL-addressable tabs provide a sound top-level model (`settings.html:22`, `settings.js:364`).
- Segmented choices are clearer and better focused than a generic dropdown (`settings.css:208`).
- Loading Facts has a complete task-oriented workflow with summary, review state, and export (`settings.html:361`).
- Nested campaign-navigation preferences are preserved while unavailable (`settings.js:921`).

## Priority Issues

### P1 — Prisma Efficiency Gains is an unscannable feature dump

**Why it matters:** unrelated switches become one high-effort checklist, so valuable features are easy to miss.

**Fix:** split it into Campaign header & copying; Navigation & Actualise; New campaign & orders; Approvals & placement; and Account & banner. Give each a compact enabled count and collapsible body. Place the eleven navigation children behind an Advanced navigation options disclosure.

### P1 — Switches are not robustly labelled or focused

**Why it matters:** row text is typically a sibling span rather than a label for the checkbox, and the hidden input does not visibly transfer focus to the slider (`settings.html:69`, `settings.css:454`). Keyboard and screen-reader users cannot reliably identify each control.

**Fix:** programmatically associate every label and input, make the row a full labelled hit target, and add a clear focus ring to the visible switch.

### P1 — Changes do not consistently communicate outcome or persistence

**Why it matters:** users cannot tell whether a toggle saved, failed, or needs a Prisma-tab reload (`settings.js:286`).

**Fix:** show a quiet inline Saved / Could not save state near the changed control, plus a section-level note that changes apply after reloading Prisma tabs.

### P2 — Row-level cards and action colours create visual noise

**Why it matters:** each option is its own pale rectangle (`settings.css:392`) and actions use unrelated colours (`settings.css:347`), so the page feels accumulated rather than designed.

**Fix:** use grouped list sections with dividers, reserve colour for status and the primary action, and standardise button hierarchy.

### P2 — Destructive or high-impact actions lack context

**Why it matters:** Reset is immediate (`settings.html:377`) and custom-reminder export relies on a browser alert (`settings.js:1756`).

**Fix:** label the reset precisely, confirm only irreversible data/history removal, and use the established status/toast pattern instead of alerts.

## Persona Red Flags

- **Alex, power user:** no search, category collapse, filter, or recently changed view; the eleven-child navigation block makes rapid configuration slow.
- **Sam, accessibility-dependent user:** label association and visible switch focus are weak, and the 50×24 switch is smaller than a robust 44px touch target. Tabs and segmented controls are stronger, so interaction quality is inconsistent.
- **Jordan, first-timer:** terms such as Optimise, Actualise, CL/PR/CA, and Billing Check lack outcome descriptions. The user cannot confidently predict an enabled switch's effect or when it takes effect.

## Minor Observations

- Label grammar varies across title case, sentence case, colons, quoted UI names, and verbs.
- The fixed 800px layout lacks broad responsive treatment (`settings.css:25`).
- The friendly closing feedback line is disconnected from the operational tone (`settings.html:530`).
