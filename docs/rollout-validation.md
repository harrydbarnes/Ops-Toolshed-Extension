# Rollout feature validation for the company pilot

Use a test Chrome profile with the unpacked extension reloaded at `chrome://extensions`. Reload each open Mediaocean tab after updating the extension. Record the extension build date, Chrome version, account location, legacy/new Orders UI, and whether the tester books on Prisma. Use only approved test campaigns and approver addresses. A Jest pass is not proof of the live Prisma workflow.

## Monday test order

The user reported that clipboard copy, Paste Approvers/Favourites, and normal route navigation worked on 22 September. The new pre-submission watch behaviour was added afterwards, so reload the extension and Prisma again before Monday's checks. A quick repeat of those three passed areas is worthwhile, but the detailed remaining checks are below. Mark each item pass/fail/not available with the campaign ID, route, time, and screenshot or short recording for any failure.

1. **Pre-submission watch (new; highest priority).** On an approved test campaign whose workflow says **Not Submitted**, open Campaign Approvals and click **Track current campaign**. It must appear under **Watching for Submission**, not **Pending Approval**, and remain there after **Check now**, waiting at least five minutes, a page reload, and a browser restart. It must not show an approval notification. A manager should be able to do this without submitting the campaign personally. Use the item's ✕ control to confirm a watch can be removed, then add it again.
2. **Submission transition and approval.** Submit that test campaign through the normal Prisma workflow, or have an authorised colleague submit it while the manager's browser remains open. Use **Check now** or wait up to five minutes. It must move from **Watching for Submission** to **Pending Approval** once Prisma reports **SUBMITTED**. Once Prisma reports **APPROVED**, it must move to **Approved Campaigns** and notify once. A browser restart must retain the current state. Do not submit a live client campaign just to test the extension.
3. **Polling concurrency.** With two test campaigns, submit them close together and press **Check now** while the second submission is happening. Both must remain tracked. If feasible, resubmit one during an in-flight check; an older check must not remove the new pending record or produce a false approval notice. Exercise dismiss, Clear All (approved only), and the Approval Tracking off/on setting. Disabled tracking must stop checks; reenabling must resume them.
4. **Non-Prisma first run.** In a fresh test Chrome profile, choose **I don't book on Prisma**. Complete setup. The Prisma tour must not start, Prisma controls must not appear after reloading a Prisma tab, while shared popup links, Approvers, and timesheet reminder remain available. Settings must identify the non-Prisma profile and hide Prisma tour actions.
5. **Profile change.** In Settings choose **Change setup profile → I book on Prisma**. Complete the three-step setup and optional tour. After reloading Prisma, its controls must return and the feature preferences must be retained. Switch back to the non-Prisma profile and reload Prisma; controls and background approval checks must stop.
6. **Clipboard and approver quick regression.** Repeat one campaign/Order copy and paste its exact value into Notepad. In Internal Approval, repeat **Paste Approvers** and **Paste Favourites** with valid test recipients. Each should select each recipient once, preserve unrelated clipboard contents, and leave manual entry working. Synthetic page clicks are covered by automated tests; ordinary clicks must still work.
7. **Routes and panels quick regression.** Navigate Plan, Buy, Actualise, legacy Orders and new Orders without full reloads where access allows. Verify the Approver Widget, Help Guides, Campaign History, approval panel, and native Prisma controls remain visible and clickable only where appropriate. Confirm no new extension console errors.
8. **History under a large grid.** Open a large campaign grid, scroll, edit as normal and switch tabs while History is enabled. Its link and search must keep working after Prisma replaces the header. Compare Chrome Performance recordings on the same page with History on and off; report persistent long tasks or noticeable lag.
9. **Data and permissions sign-off.** Read [Data, permissions and privacy](data-and-permissions.md) against company policy. In a test profile, save a test Meta token, refresh Meta data, then remove the token. Export Diagnostics and History containing only test campaign data; verify contents and clearing controls. Confirm the listed external font/CDN requests are acceptable for company rollout.
10. **Feature and release content.** Compare visible Settings toggles and the in-extension feature explorer against [the generated catalogue](feature-catalogue.md) and r1.9 Release Notes. Names, explanations, defaults, preview images and the new watch behaviour must match. A technical checker should run `npm run check:feature-docs`.
